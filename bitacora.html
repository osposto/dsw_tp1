Bitácora del Proyecto

Registro cronológico de decisiones de diseño, dificultades técnicas encontradas y soluciones aplicadas durante el desarrollo colaborativo del TP1.

1. Arquitectura Base, Navegación y Enfoque Mobile-First

Etapa 1 · Estructura y CSS

Decisiones tomadas: Se diseñó una arquitectura limpia con un tema oscuro (Dark Theme) centralizado en css/styles.css utilizando variables CSS (Custom Properties) y tipografías de Google Fonts (Inter y JetBrains Mono). Se implementó una barra de navegación superior persistente y botones de retorno explícitos (← Volver al equipo) en todas las páginas individuales para que el usuario nunca dependa del botón "Atrás" del navegador.

Dificultades encontradas: Al pasar el equipo de 4 a 3 integrantes, la grilla en resoluciones intermedias (tablets) dejaba la tercera tarjeta desalineada, y al aplicar una regla de centrado (grid-column: 1 / -1) en min-width: 900px, esta se heredaba en cascada hacia pantallas de escritorio (1200px+), forzando dos filas en lugar de una.

Soluciones aplicadas: Manteniendo el paradigma Mobile-First (1 columna base en móviles y mejora en 400px), se encapsuló el diseño de 2 columnas más tarjeta inferior centrada dentro de un rango acotado (@media (min-width: 900px) and (max-width: 1199px)). De este modo, al alcanzar el breakpoint de 1200px, la grilla pasa limpiamente a repeat(3, 1fr) sin necesidad de sobreescribir o deshacer estilos previos.

2. Optimización Multimedia y Filtro Dinámico en Portada

Etapa 2 · Portada y Recursos

Decisiones tomadas:En la portada (index.html) se programó con JavaScript (js/main.js) un buscador interactivo en tiempo real que filtra las tarjetas de los integrantes tanto por su nombre como por sus etiquetas de habilidades (data-skills). Asimismo, se estandarizó el uso del formato moderno .webp para todas las fotografías, pósters de cine y portadas de discos.

Dificultades encontradas: 1) Las distintas proporciones de los pósters y portadas de álbumes deformaban las tarjetas. 2) Durante las pruebas iniciales sin imágenes locales, un manejador onerror apuntando a un recurso inexistente generó un bucle infinito de recarga en el navegador.

Soluciones aplicadas: Se aplicó object-fit: cover con proporciones estandarizadas (1:1 para avatares y álbumes; 2:3 para pósters de películas) y compresión previa a formato .webp, logrando cargas instantáneas y simetría visual en todos los perfiles.

3. Modularización JavaScript e Integración del Equipo

Etapa 3 · Perfiles y Git

Decisiones tomadas: A partir de una plantilla unificada (plantilla-perfil.html), se decidió separar la lógica de JavaScript en archivos independientes por integrante (js/perfil-1.js, js/perfil-2.js y js/perfil-3.js). Cada miembro personalizó su componente interactivo aportando un enfoque técnico propio:

  • Guillermo Escobar (perfil-1): Implementó animaciones elásticas de entrada y salida (Bounce In / Bounce Out) utilizando la Web Animations API nativa (Element.animate con curvas cubic-bezier).
  • Orlando Sposto (perfil-2): Desarrolló el sistema de fichas técnicas dinámicas con inyección de pósters, sinopsis y citas célebres destacadas mediante manipulación del DOM.
  • Adriana Van Den Dooren (perfil-3): Incorporó mejoras avanzadas de accesibilidad web (a11y): navegación completa por teclado (Tab, Enter, Espacio y Escape), atributos ARIA (role="dialog", aria-hidden) y restablecimiento automático del foco al cerrar el modal.

Dificultades encontradas: Durante el trabajo simultáneo en Git se produjeron divergencias entre ramas locales y remotas al subir avances en paralelo, además de una corrupción puntual del archivo .git/index en el entorno local.

Soluciones aplicadas: La separación modular en archivos HTML y JS individuales por integrante permitió fusionar (git merge) los cambios de cada miembro sin conflictos de código. El índice de Git se reconstruyó limpiamente mediante git reset manteniendo intacto todo el historial de commits del equipo.
